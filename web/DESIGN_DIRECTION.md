# FOLO Studio design direction

Written after round 4 by a design-director pass (Claude Opus 5.5) over every round-4 screenshot and the source.
Round 5 onwards is implemented against this document; per-issue fixes come after the system changes in §5.

## 1. Diagnosis

The screens are competent everywhere and memorable nowhere. Each weak area traces back to the system:

| Area | Local / structural | Why |
|---|---|---|
| Data viz (5.5) | Structural | Four chart implementations (LineChart, Histogram, PrCurves, ConfusionMatrix) with different axis typography; every single-series chart is sky-blue with an area fill, so a run page is six equal-weight charts; hover opens six floating tooltips that repeat the legend values. |
| Typography (6) | Structural | 11 px in 79 places; hard-coded 9/10/15 px; mono leaks into numbers (Playground, PR/histogram/confusion ticks); panel titles 13/500 = body. |
| Colour (6) | Structural | Lime means primary button, running, hero metrics, "best" across incomparable datasets, selected cards, theme previews, sidebar overline. Status hues used as links ("See Health" red, "+1 queued" blue); queued grey on Overview, blue on Runs. |
| Consistency (6) | Structural | No shared table (eight hand-rolled `<table>`s), no chart panel, no page grid. Errors look different per screen. Mobile lists use three card patterns; the top bar shows a title on some screens, only the logo on others. |
| Spacing (6.5) | Mostly structural | Off-grid 10 px (16×), 5, 7, 3 px in components; no column system (8+4, 7+5, thirds), so panel bottoms and inner edges never align. |
| Responsiveness (6.5) | Conceptual | Phone = desktop stacked in one column. The run page on a phone opens with Stop then six charts. |

**The five structural caps**
1. No primitives for the three jobs that make up 80 % of the app: **table, chart panel, page/section grid.** Every screen re-solves them slightly differently.
2. **Colour is decoration, not meaning.** Hue should identify an entity (a run in Compare, a class); right now it is applied by default.
3. **Lime is diluted** (20+ uses), so it no longer reads as "now" or "act".
4. **Type scale too small and too wide**: 7+ sizes per screen, most text at 11–12 px, no panel-title step.
5. **Equal-weight dashboards**: Run, Model, Overview and Compare tile same-weight panels with no single focal object.

## 2. Principles

1. **Density.** List rows 36 px single-line; dense rows (per-class, detections, config, labels) 28 px; two-line rows only on phones (56 px). Panel header a fixed 40 px with 16 px side padding; panel body padding 16 (12 dense); gap between panels 16 everywhere. Every panel-like surface (ui/Panel, KPI strips, Health, cards, folds, callouts and their skeletons) draws its outer edge with one alias, `--line-panel` (`base.css`: `line.default` in light, `line.subtle` in dark), never a `--line-*` of its own or a theme override; a strip whose 1 px dividers are a line-coloured background clips it to the padding box (`background-clip: padding-box`), or the translucent edge composites over it and reads darker (`design/panelEdge.test.ts`).
2. **Page grid.** Content max 1200 px, 12 columns, 16 px gutters. Allowed splits: 12, 8+4, 6+6, 4+4+4. Panels in a row stretch to equal height; panel titles share a baseline; plot left edges align to column edge + 16. A right rail is always 4 columns and sticky (top 64).
3. **Typographic rhythm.** One job per size, at most six per screen: 20/600 page title · 14/500 panel title · 13/400 body and table cells · 12/400 meta, table headers, legends · 11/400 chart ticks only · 24/600 KPI values. At most one 32/600 hero number per page. No 44 px step, no uppercase overlines in app screens (micro only for key hints). Mono for identifiers, paths, logs, JSON and CLI, never for a number. Helper text 12 px, ≤ 60 characters per line. **Identifiers vs names:** an architecture (`folo-s`), the checkpoint a run started from (a model cited as a source, `folo-s-coco80`, or a `.folo` file), a server id (`r_…`, `m_…`) and a named optimizer are identifiers and always mono, through one component, `ui/Ident` (a link with `href`), in tables, chips, meta lines, rails and sentences alike; the source scan in `ui/Ident.svelte.test.ts` fails on a bare one. A run's, model's or dataset's own name, where it labels that entity (its row, title, chip, crumb or link), and class names are names: sans. Prose values in an identifier slot ("From scratch", "auto") stay sans.
4. **Chart frame.** Header (40 px): title 14/500, unit or qualifier tertiary, controls right (at most one segmented group). Legend row (24 px) directly below, starting at the plot's left edge. **Legend values are the readout**: last value at rest, cursor value on hover; one shared vertical cursor across synced charts; no floating tooltip. Plot: horizontal gridlines only (3–5), baseline axis, y ticks right-aligned in a 32 px gutter, 11 px Geist ticks; the x-axis name goes into the header ("by epoch"). A chart panel never contains a second legend, a paragraph, an overline, a floating "best" label (use a 6 px lime ring marker and the value in the legend), or more than one area fill.
5. **Colour by entity.** Hue identifies an entity: a run in Compare, a class in evaluation. A single run's metrics are drawn in ink: the primary metric `text.primary` 1.5 px, secondary metrics `text.tertiary` with dash patterns. Loss: total primary; box / cls / dfl are three quantities, so they take the hues design/README.md gives them in both apps (box amber, cls violet dashed, dfl teal dotted). Histograms and timing bars neutral ink. Area fill only on the page's single focal series, at 8 %.
6. **Lime means "now" or "the one action".** Allowed: one primary button per viewport, focus ring, running dot and live progress, selected detection, best-epoch marker. Never metric text, meters, nav icons, selected cards (use `line.strong` + `bg.active`, neutral), illustrations, previews. Status colours: dot + word in tables, tinted fills only in banners; queued and stopped neutral. Links are `text.primary` (underline on hover), never a status hue. Class colours only for classes.
7. **Tables.** One system: the global `.table` class (`lib/design/base.css`) is the single source, so every table looks the same without local styles. Header 32 px, 12/500 tertiary, sentence case; rows 36 px single-line, `.dense` 28, `.tall` 48 (a name over one meta line); the first cell (or `.lead` when a checkbox or index comes first) is 13/500 primary and its second line is `.sub` (12/400 tertiary); everything else 13/400 (secondary for specs and reference columns); numbers right-aligned (`.r`) and tabular with the unit in the header, not the cell; at most one inline bar column (48 px, neutral); status as dot + word, not a pill. Rows that open something are `.link` (hover fill); selection is `.on` / `aria-selected`: `bg.active` and a 2 px accent bar on the leading edge (every list: tables, detections, classes); a keyboard-focused row (rowNav) draws the focus ring as a closed rectangle 4 px inside the row, so on a selected row the ring and the leading bar stay two shapes with a gap between them; row checkboxes keep their column's width but show only on the hovered or keyboard-focused row (so X is discoverable), on selected rows, and on every row once any is selected; on touch they always show, 20 px in a ≥ 44 × 44 px cell. A checked box is neutral (`text.primary` fill, inverted check): the row's one lime mark is its leading bar. **Responsive columns** are one global rule in `base.css`: `.hide-xl` (< 1440), `.hide-lg` (< 1280), `.hide-md` (< 1024), `.hide-sm` (< 768) go on the `<th>` (a `SortHeader` takes it as `class`) and on every `<td>` of the column, skeleton rows included; a component never defines its own, since a scoped rule cannot reach a header rendered by `SortHeader` (`listTables.svelte.test.ts` checks header and body cells per row at each width). A sortable header is `ui/SortHeader` (a button with the direction mark, `aria-sort` on the sorted column only, the mark's slot kept so labels never shift; number columns put the mark before the label). List tables (Runs, Models, Datasets) take `use:rowNav` and `data-row`: one roving tab stop, J / K and ↓ / ↑ move it, Enter opens, X selects for Compare on Runs, J / K enter the list when nothing has focus. The defaults are wrapped in `:where()`, so a table's own classes always win; a table that needs a local rule for the header, the first column, hover or selection is a bug in the system, not in the table.
8. **States** render inside the frame that would hold the data. One height policy for every list (Runs, Models, Datasets, Overview's Recent runs): on desktop the frame keeps its header row and the state is a compact block under it, the message and its actions with the panel's 16 px padding, never held at the loaded rows' or the skeleton's height. On phones (no header row) the card is the content plus 24 px (12 above, 12 below). In a table that is `ui/TableState`; panels side by side in a row stretch to equal height, so a short state in one never leaves the other hanging. Loading is the exception: the skeleton mirrors the loaded rows. Empty: 16 px icon (no frame), one sentence, one button (secondary unless the page has no other primary). Error: same placement, `danger.text` title, a cause sentence, a mono request line, Retry. A failure behind every request (offline) is said once, where the page's focal object would be; the other panels keep their frames with one quiet line. A page whose header holds a create action (Runs' New run, Datasets' Add dataset) calls `ownCreateAction()` (`shell/crumbs`) and the top bar's New run steps aside while it is mounted, so one corner never holds two create buttons. Offline, the actions that need the server (New run, Add dataset, the top bar's New run) are disabled, not lime, with the reason "Server offline" as a tooltip and as their accessible description (`ui/Gate`); the same wrapper gives every disabled control its reason ("Select 2–4 runs to compare"). Loading: skeletons mirror the final geometry exactly; charts show the axis frame without a line; an image's skeleton (`Skeleton image`) is a raised fill with `line.strong` viewfinder corners (in light, a grey well a step below the app background, since a near-white raised fill reads as a blank page), so it never reads as an empty photo. No dashed boxes, no centred cards: Not found is the same inline EmptyState in the page's content slot. Page subtitles are fixed descriptions; counts that arrive with the data live in the toolbar row, so nothing above the content jumps on load.
9. **Motion and focus.** Keep the tokens. Drop the page-enter translate. Live values never tween; chart domains re-ease at most once per epoch. JS transitions (`svelte/transition`) take their duration from `ui/motion.ts`, which is 0 under reduced motion (the CSS rule cannot reach them). A new page (path change) moves focus to its `h1` (`data-route-focus`; the main region while a page has none yet) and starts at the top; a query or filter change keeps focus where it is. Dialogs, the palette and menus return focus to their opener (`ui/focus.ts`). Programmatic focus shows a ring only when it is `:focus-visible`. Toasts never take focus (a click on their buttons does not move it, nothing auto-dismisses while focus is in the stack, and closing the toast that holds keyboard focus hands it back to where it came from, never to `<body>`). A dialog body that scrolls shows a shade at each edge with more behind it. Single-character shortcuts (N, G …, [, ?, list J / K / X) can be turned off in Settings (`ui/keyPrefs`, WCAG 2.1.4); Mod+K and a focused component's arrow keys always work, and key hints for the single keys hide while they are off; the shortcuts reference then lists those keys in a section of their own, "Disabled in Settings", apart from the ones that still work (the image inspector's keys among them). Key names follow the platform ("Ctrl K" or "⌘ K", never both). Touch-only devices (`(hover: none) and (pointer: coarse)`) get no shortcuts reference: no palette entry, no "Show shortcuts".
10. **Page headers.** One rule on every page (`shell/Page`): from 768 px up the actions sit on the title row, right-aligned and centred on the title's line, whatever the length of the lead and meta lines, which run the full width above and under it. Below 768 px the title is in the top bar; the page keeps its primary action (a short word) and its secondary actions fold into one ⋯ menu: pass them as `more` and Page renders them as secondary buttons on wider screens and as the menu on phones. A page with a long meta line passes a short `subPhone` (one line): on phones the header is then one row, that line on the left and the primary and ⋯ on its right, and the content starts 16 px under it (Runs, Datasets, Models; Run, Model and Dataset detail do the same with their own meta lines). A secondary action that belongs to a list moves into the list on phones (Runs' Compare sits in the list's header row, by the checkboxes).
11. **Invalid fields.** A field in error (`aria-invalid="true"` on an Input, a Select, a Segmented group or a chips field) has a `danger.solid` 1 px edge at rest and on hover, and when focused a danger ring instead of the lime one (`base.css` overrides `--line-control`, `--line-control-hover` and `--focus` on it). The Field's message under it is `danger.text` with a danger icon, `role="alert"`, and the control's `aria-describedby`, so the error is never red text alone.
12. **390 px is its own concept.** Top bar always back (or logo) + page title + search; the H1 is not repeated. Lists are 56 px rows (name, one meta line, metric right), never cards. A detail page leads with its focal object; everything else sits behind a segmented control. Dialogs become bottom sheets; rails become sheets opened from a header button. A title-only page header takes no room on phones (the top bar has the title), so the first content sits 16 px under the bar on every screen. A page with a bottom dock (New run's Start bar) hides the tab bar while the dock is mounted (`use:dock` from `shell/dock.ts` sets `<html data-dock>`: `--tabbar-h` drops to 0 and the dock moves to the screen's edge), so the fixed chrome at the bottom is one bar.
13. **Buttons.** One primary per viewport. In light, the lime primary carries a neutral 1 px `line.default` edge outside the fill (never an olive one). Disabled filled buttons, primary included, look the same in both themes: `bg.raised`, `text.disabled` label, `line.default` edge, no shadow (never a faded lime); a loading button keeps its look and shows the spinner. The quiet destructive control on a page (Stop) is a secondary button with `danger.text` label and icon, no tinted fill; its dialog holds the solid confirm. One action has one name everywhere ("Generate sample set").
14. **Supporting text is at least 12 px** (`type.sm`): meta lines, captions, badges, tab-bar labels, technical details, key caps (`ui/Kbd`, 20 px tall, and the tooltip's keys). 11 px is for chart ticks only. Dialogs set their body and description in `base` 13 px, at least 480 px wide where the viewport allows (`ui/Dialog`; phones get a bottom sheet). Helper lines (Field and Switch hints, Settings notes) stop at 60 characters a line.
15. **Form pages** (Settings) use `Page narrow`: the 720 px form column starts on the shared content edge, like every page's title and first panel, with a sticky rail of section anchors on its right.

## 3. Per screen

**Overview.** Focal point: the live run. Remove the demo-data subtitle (the sidebar says it), the Datasets / Playground header buttons (they duplicate nav), the Datasets card row and the System card's two rings (fold GPU and memory into one meta line on the live card: `RTX 4080 SUPER · 94 % · 21.4 / 64 GiB`). Live run full width: epoch hero left (4 cols), mAP chart (8 cols, the page's one area fill). Below: Recent runs (8) + Best models rail (4). One hero, one table. A fresh install shows the three steps and, under them, the live card's frame in still placeholder geometry, so the page shows what it becomes.

**Datasets list.** Almost right. Single-line 36 px rows: name, format as tertiary text (no boxed badge), path mono tertiary, split counts as columns, the class-balance strip 160×6 as the signature. Empty state: no in-panel primary (the header has it). Migrate to `DataTable`.

**Dataset detail.** Header: name + one meta line; Delete into a `…` menu. Images: one toolbar (split segmented left, multi-select class picker with swatches, Boxes / S M L right); grid gap 8. Inspector: 28 px label rows, canvas full dialog width. Stats: re-layout. Health issues as a banner list at the top (only when present; at rest one summary line, open a plain "Health · N checks" heading over the findings, two columns from 1024 px); class balance full width as the focal point; the two histograms below at 6+6 in neutral ink; KPI strip from six cells to four; "See Health" a neutral link.

**Runs list.** Dataset and model as columns instead of a second line; no always-visible checkboxes; sparklines neutral with a lime endpoint only while running; queued neutral. `DataTable`, 36 px rows.

**Run detail (re-layout).** Header: name + status + one meta line; the completed / failed banner collapses to one line under the header. The KPI strip becomes **KPI tabs** (Vercel analytics): mAP50-95, mAP50, P·R, Loss, LR, img/s, each showing its value; clicking selects the **one main chart** (12 cols × 320 px). Below: Validation samples (8) + rail (4) with a compact per-class list and a collapsed Config; Logs a tab next to Samples. Remove the "Training curves" overline and the standalone LR / throughput panels; the So far / Full run toggle moves into the chart header.

**Compare.** One chart with metric tabs instead of the 2×2 grid (four legends repeating run names). The run chips are the legend, values update on hover. The side-by-side table is the real comparison: differing values in 500 weight, identical rows collapsed ("6 identical settings"), status dot + word. The info banner becomes a 12 px tertiary note under the chips. The fourth series must be visible.

**New run.** Sound. Sticky Summary rail so Start training stays visible; drop per-model metric bars (keep the numbers); selected cards `line.strong` + `bg.active`, no lime dot; CLI block collapsible at the rail's foot; the augmentation preview sticks while the sliders scroll.

**Models list.** Group rows under a 32 px section header per evaluation dataset; the top row of each group marked with tertiary "best" text (no lime across datasets). No per-cell meters, no boxed arch badges. Filters in a toolbar row under the header, as on Runs.

**Model detail.** Hero metric in ink; the four KPI cards with meters become one strip. PR curves: all classes `text.tertiary` 1 px, mean in primary, hovered / selected classes take their hue (fixes 80-class spaghetti). The per-class table is the PR legend (row hover highlights its curve); drop the duplicate AP50 list. Confusion matrix: one sequential luminance ramp, cell numbers in Geist, cells at most 48 px (the rail beside it takes the rest; two lists side by side once it is 560 px wide); the scale labels every block as a share (None, <1%, 1%, 5%, 10%, 100%). A matrix that scrolls sideways (phones) has its column range, a jump to the background column and the readout above the grid. The curves (8) and Details (4) stretch to one height; the per-class table, sharing their traced classes, is a row of its own. A KPI strip's ⓘ follows its first label in every layout (desktop strip and phone grid alike).

**Playground.** The strongest screen. No mono numbers; canvas height viewport − 220; threshold helper paragraphs become tooltips; timing phases in neutral shades. Phones: full-bleed image, thresholds in a bottom sheet, the confidence slider pinned.

**Settings.** Forms max 720 px. Drop the shortcuts table (link the `?` dialog). Theme previews in neutral ink. Reconnect secondary until the URL changes. Theme previews are one radiogroup, each card's name under it and the chosen one saying "Current" in words, not only with its ring. System: each capability is one plain sentence and at most one action that docs/CLI.md or docs/GPU.md backs ("Start `folo serve --tensor-cores` to use them"); the server's own words sit in a folded, copyable Driver report.

## 4. What a 9 looks like here

1. **Vercel Analytics / Observability**: KPI tabs switching one large chart, a single hue, legend as readout, cursor without a floating box → Run detail, Compare, the Overview live card.
2. **Linear issue list**: 36 px single-line rows, muted meta columns, checkboxes on hover, group headers → Runs, Datasets, Models (grouped by dataset).
3. **Linear issue view**: main column + sticky properties rail → Run detail, Model detail, New run.
4. **Vercel deployment page**: status dot + one meta line; failure as a one-line callout, not a big tinted card → run banners, error states.
5. **Raycast**: monochrome icons, exactly one accent moment per view → the lime rule.
6. **Linear empty states**: small, inline, frameless, one action → every empty state.
7. **Vercel Usage**: one big number, supporting numbers in ink → Model and Dataset KPI strips.

## 6. Checks in the shoot

`npm run shoot` runs two checks on every shot after its setup and lists what they find together, printed last, boxed,
and saved to `qa.txt` beside the shots (`qa-<filter>.txt` with `--only`). The list never fails the shoot; review it with
the screenshots. It must be empty before a round goes to review.

**Blank sections.** A selected control whose content renders nothing is the bug round 19 shipped (the phone rule that
hid every `.rail` left Model's Details, Run's Classes and a queued run's Config blank behind a selected picker):
- every selected tab (`[role=tab][aria-selected=true]`) and every checked radio with `aria-controls`: the element it
  controls must exist, be visible (not `display: none`, itself or through an ancestor) and be taller than 40 px;
- every checked radio of a section picker without `aria-controls` (a Segmented labelled "Show", or one in
  `.phone-pick`): the content under the picker in `main` must reach 40 px;
- `main`: the content under the page header (`.page > header`, or main's top when the header takes no room) must reach
  80 px.

Content is what a reader sees: text, images, canvases, SVG, form controls, and boxes with a fill or an edge (panel
frames, skeleton blocks); fixed bars (the tab bar, docks) don't count. A section picker's sections should therefore keep
their content in the page's own region, not in a column a breakpoint can hide. The check was proven against the round-19
rule: put back `.app :global(.rail) { display: none }` in `App.svelte` and it flags `model-detail-details`,
`run-live-phone-classes` and `run-queued` at mobile.

**Horizontal overflow.** The page wider than the viewport, and any element whose content is wider than its box
(`scrollWidth > clientWidth + 1`, innermost box, naming its widest child). It skips hidden content, ellipsis truncation, negative-margin hit areas, positioned decorations and deliberate scrollers
(`data-scrolls`, or an `overflow-x: auto` box with a fade mask). A plain scrollbar is not a deliberate scroller: a list
table that needs one at a width it was designed for is the bug the check exists to catch. Both checks share the list above.
